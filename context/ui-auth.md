## Selectors

Re-confirmed live, unchanged from the earlier run:

| Field/control | Selector | Notes |
|---|---|---|
| Mobile number input | `input[name="Mobile Number"]` (also `id="Mobile Number"`) | Brittle — id/name contain a literal space, no `data-testid`. `maxlength="10"`. Prefer `page.getByRole('textbox', { name: 'Enter your mobile number' })`. |
| "I agree to..." checkbox | `[data-testid="login_agreeTerms"]` | Resilient, real data-testid. **Automation gotcha (still confirmed):** a decorative `<svg class="checkbox-icon">` overlay intercepts direct pointer clicks on the raw `<input>` — click the wrapping `<label>` instead. |
| Continue button (step 1) | `role=button[name="Continue"]` | No `data-testid`/`id`. Disabled until (a) mobile number is a valid 10-digit value and (b) the Terms checkbox is checked. |
| OTP digit inputs (step 2) | `[data-testid="otpVerify_otpInputs"]` — **not unique**, all 6 boxes share the identical testid; select by index (`.nth(0)`…`.nth(5)`) | 6 separate single-character (`maxlength="1"`) inputs. |
| Continue button (step 2 / OTP submit) | `role=button[name="Continue"]` | Disabled until all 6 OTP digits are filled. |
| Org-avatar menu trigger (top-left, opens Lead Management link) | `[data-testid="header_profileButton"]` → nested `role=img` | **Newly confirmed this run** — the trigger's container actually carries `data-testid="header_profileButton"`, a more resilient selector than the earlier run's `getByRole('img').first()` fallback.
