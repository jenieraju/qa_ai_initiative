## Login flow

| Step | Route/URL | Purpose |
|---|---|---|
| 1 | `/login` | Enter mobile number (`LoginInput` component, placeholder "Enter your mobile number") |
| 2 | `/login` (same route, step-switched) | Enter OTP (`OtpVerification` component) |
| 3 | `/login` (same route) — only if the account belongs to >1 organisation | Select organisation (`OrganizationCard`, via `useLazyGetOrganizationListQuery`) — skipped entirely for a single-org account |
| 4 | `/lead-management/dashboard`, `/dashboard`, or admin landing (role-dependent) | Post-login redirect target |

## Session shape in the browser

- **Storage:** `localStorage`, key `"token"` (`LOCAL_STORAGE_KEYS.ACCESS_TOKEN = 'token'`, set via `setTokensInStorage`/`setLocalStorageItem` in `Login.tsx`) — not a cookie.
- Additional related keys set on login: organisation ID (`LOCAL_STORAGE_KEYS.ORGANIZATION_ID`, `USER_ORGANIZATION_ID`).
- **Post-login redirect target:** role/org-dependent — `/lead-management/dashboard` is the relevant one for this feature's tests (a user landing in the LMS dashboard directly, or navigating there via the side nav after a generic dashboard redirect — not fully traced which is default).
- **On-page "logged in" signal:** not confirmed this pass beyond the redirect itself — recommend `ui-test-automation` confirm a stable on-page element (e.g. the side-nav's "Lead management" entry, or the dashboard greeting text) rather than relying on URL alone.
