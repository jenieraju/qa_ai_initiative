## Post-generation findings (from actually running the suite, 2026-08-24)

`ui-test-automation` generated and executed this matrix against the live dev environment. All 33 cases were implemented (31 executable, 2 documented `test.skip()`s — rows 13 and 33); 4 real locator bugs were caught and fixed only by actually running the suite, not by design alone:

- **Dashboard Conversion Funnel (row 10):** each `<li>` renders 3 `<span>` children — a decorative `aria-hidden` color dot, the stage name, then the count. An initial `:first-child` selector grabbed the empty dot; fixed to `:nth-child(2)`.
- **Leads list Status column (row 15):** the leads table is div-based, not a real `<table>`/`role="row"` structure — a locator scoped to table/row roles matched nothing. Fixed to a page-wide text match (safe since it matches exact status *values*, which can't collide with the "Status" header word).
- **Leads Analytics locations empty-state (row 21) and Agents-distribution table (row 20):** both needed 2 parent levels up from their section heading, not 1, to reach the right container.
- **Agents-distribution status headers (row 20), second pass:** each status name (e.g. "Prospect") appears *twice* on the Analytics tab — once in the "Lead Count & Revenue By Status" chart legend, once as this table's own column header — the exact same "top channel also appears in stat cards" ambiguity pattern found on the Sources page in an earlier run against this app. Fixed the same way: `.last()` per status name, since the chart renders before the table in DOM order.

Final result: **62/62 executable tests pass** (Chromium + Firefox; WebKit unavailable in this sandbox — see below), 0 failures.

- **WebKit still cannot navigate to any site in this sandbox** (confirmed against `example.com` in an earlier run against this same app, unrelated to cofee-web) — missing system dependencies from installing without `--with-deps` (no root access). Expected to work in the GitHub Actions CI runner.
- **Local parallelism above 4 workers still causes real navigation timeouts** under resource contention — `playwright.config.ts` caps local workers at 4, carried forward from the earlier run's finding.
